# 04 · Claude 交付验收契约

必须先输出主控第21节的 12 项首轮评审成果，并关联 requirement ID，随后分篇生成主控第20节的完整文档。所有文档须有：`doc_id`、`version`、`status`、`source_files`、`last_verified`、`depends_on`、`requirements`。

## 一篇系统设计的最低组成
目标、玩家动作、历史依据、对象字段、状态转移、命令权限、成功路径、失败/历史分歧、UI 页面流程、卡片/美术/声音清单、模块接口、内容编辑流程、测试 fixture、性能/存档、阶段工时、Codex Task ID。若写不出字段与实例，则不能叫“完整设计”。

## 设计评审
- 79年窗口、人物生死、周室前256/前249区分、各国有效官制和兵器年代正确；
- 玩家与NPC同受规则约束，卡片/历史实体语义独立；
- 地图/经济/事件/战争共享同一世界状态；
- 战役结果一次性事务回写；
- 可运行结果有真实截图、日志和测试；
- 美术资产是真正可分层、可绑定、可导入的生产内容，不能只有效果图。

## 文件状态
`DRAFT → REVIEW → APPROVED`（策划）与 `READY → IN_PROGRESS → REVIEW → DONE`（工程）分开追踪。只有用户批准后才能冻结新的架构取舍或删除既定核心需求。
